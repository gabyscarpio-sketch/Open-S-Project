Prompts de UX para el Frontend (React/Next.js)
Usa estos prompts cuando estés en los archivos de tu directorio frontend.

1. Prompt para la Búsqueda de Pacientes (Evitar la Fricción)
El objetivo es que encontrar a un paciente sea rápido e intuitivo, no una tarea tediosa.

"Usando React, TypeScript y Tailwind CSS, crea un componente PatientSearchBar.

Debe tener un campo de texto con un ícono de lupa dentro.

Mientras el usuario escribe (con un debounce de 300ms), muestra un sutil indicador de carga debajo de la barra.

Si la búsqueda no devuelve resultados, no muestres una lista vacía. Muestra un componente amigable con un mensaje claro: 'No se encontraron pacientes con ese nombre.'

Los resultados deben aparecer en una lista desplegable con efecto hover en cada nombre para indicar que son seleccionables."

2. Prompt para la Interfaz del Asistente Virtual (Generar Confianza y Fluidez)
El chat debe sentirse vivo y receptivo, no como un formulario estático.

"Quiero mejorar la UX de mi componente de chat del asistente. Realiza los siguientes cambios:

Cuando el usuario envía una pregunta, el botón 'Enviar' debe desactivarse y la pregunta debe aparecer inmediatamente en el historial de chat con un estado visual de 'enviando' (por ejemplo, un poco más opaco).

Mientras se espera la respuesta de la API, muestra un indicador de 'escribiendo' con tres puntos animados en el lado del asistente. Esto le asegura al usuario que el sistema está trabajando.

La respuesta del asistente no debe aparecer de golpe. Haz que el texto se muestre palabra por palabra (efecto 'streaming' o 'máquina de escribir') para una experiencia más dinámica y natural.

Cada mensaje de respuesta del asistente debe tener un pequeño ícono al lado para 'Copiar al portapapeles' que aparece al pasar el ratón por encima."

3. Prompt para Visualizar Datos (Claridad y Jerarquía)
El historial médico puede ser denso. Debemos hacerlo escaneable y fácil de digerir.

"Crea un componente MedicalHistoryTimeline para mostrar los registros de un paciente.

Usa un diseño de línea de tiempo vertical. Cada evento en la línea de tiempo será una tarjeta.

Cada tarjeta debe mostrar la fecha de forma prominente en la parte superior.

Usa íconos de diferentes colores para diferenciar tipos de eventos a simple vista (ej: un corazón para cardiología, una pastilla para prescripciones, un matraz para resultados de laboratorio).

Si una descripción es muy larga, debe estar colapsada por defecto, mostrando solo las primeras 3 líneas con un botón de 'Ver más' para expandirla. Esto mantiene la línea de tiempo limpia y ordenada."

4. Prompt para el Feedback de Acciones (Confirmación y Seguridad)
El usuario debe saber siempre si sus acciones (guardar, borrar) tuvieron éxito o no.

"En mi formulario para añadir un nuevo registro médico, implementa el siguiente flujo de UX:

Al hacer clic en el botón 'Guardar', este debe cambiar su texto a 'Guardando...' y mostrar un spinner giratorio a su lado, además de quedar deshabilitado para evitar doble submission.

Si la operación de guardado es exitosa (la API devuelve un 200), oculta el formulario y muestra una notificación 'toast' de éxito en la esquina superior derecha que diga 'Registro guardado correctamente' y se desvanezca después de 3 segundos.

Si la API devuelve un error, el botón debe volver a su estado original ('Guardar') y debe aparecer un mensaje de error claro y conciso justo debajo del botón, no un alert() genérico."
